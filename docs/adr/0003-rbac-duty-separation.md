# ADR-0003：ADMIN 与 REVIEWER 职责分离

日期：2026-08-13

## 状态

Accepted

## 背景

平台既有账户、交易、导入和对账等业务写入，也有风险任务决策。让同一角色既创建业务事实又审核自己的异常，会削弱职责分离和审计价值。系统同时需要清楚区分未认证和已认证但权限不足。

## 决策

登录保持匿名；账户、交易和任务读取允许 `ADMIN` 与 `REVIEWER`。账户/交易写入、文件上传和发起任务只允许 `ADMIN`；审核决定只允许 `REVIEWER`。缺失/无效身份由 AuthenticationEntryPoint 返回 401，角色不足由 AccessDeniedHandler 返回 403。所有关键成功操作写入审计。

## 理由

- 防止业务管理员直接批准自己产生的风险任务。
- 401/403 分离让客户端、测试和排障能够区分身份问题与授权问题。
- 明确的路由权限矩阵可以通过 HTTP 与数据库无副作用断言验证。

## 后果

演示和验收需要维护两个临时身份；`ADMIN` 即使权限更广也不能做审核决定。新增接口必须明确读取/业务写入/审核决策类别，并同时更新安全测试和 API 文档。

## 替代方案

- **单一全权管理员**：实现简单，但无法证明职责分离，并弱化审核工作流。
- **只在 Service 层手工判断角色**：容易漏掉路由，错误响应不一致；保留业务状态校验，但入口授权交给 Spring Security。
- **细分更多角色**：当前业务和团队规模没有证据支持更多权限组合。

### 真实业务闭环

使用真实登录接口取得 ADMIN/REVIEWER JWT，并通过 HTTP 完成：

```text
ADMIN 登录
  → 创建账户和 MANUAL 交易
  → CSV 首次上传：202
  → 同一原始文件重复上传：200 + duplicateFile=true
  → RabbitMQ 异步导入：SUCCESS，1 行成功
  → 创建对账任务：202
  → 重复触发对账：200 + duplicateRequest=true
  → 对账完成：1 条 MATCHED
  → LARGE_AMOUNT 风险命中
  → REVIEWER 查询并发审核
  → ADMIN 查询审计日志和统计总览
```

### 并发、缓存和限流

- 同一审核任务携带相同 `version=0` 并发提交，返回一条 `200` 和一条 `409 REVIEW_VERSION_CONFLICT`；最终状态为 `CONFIRMED`、版本为 `1`。
- 同一审核任务最终只有一条 `REVIEW_CONFIRMED` 审计记录。
- 统计缓存连续命中时 `generatedAt` 保持不变；审核提交后统计中的 `pending/confirmed` 计数发生正确变化，证明提交后失效生效。
- 登录限流结果为 `401,401,401,401,401,429`，`429` 带 `Retry-After`。
- 上传限流结果为十次 `400` 后第十一次 `429`，并带 `Retry-After`。
- 停止 Redis 后，统计接口回源 MySQL、登录继续成功；Redis 恢复后统计接口重新正常工作。

### 幂等与审计

- 重复文件、重复对账请求和并发审核均未产生重复业务状态。
- 异步导入/对账重复消息、重试、风险规则重复评估和审计终态重放由聚焦测试与完整回归覆盖，结果无重复副作用。
- `CSV_UPLOAD_ACCEPTED`、`RECONCILIATION_COMPLETED`、`REVIEW_CONFIRMED` 对本次验收目标各保持一条记录。

## 4. 偏差、限制与经验

- 本地 Maven 集成测试会输出 Flyway 对 MySQL 8.4 高于已测试版本的兼容性提示；本次 V1～V10 校验、完整测试和真实验收均通过，该提示仍需在后续升级依赖时复核。
- Redis 仍只是可重建缓存和单实例固定窗口限流组件，不是业务真源；Redis 故障时统计回源、限流按当前契约 fail-open。
- 当前限流不提供分布式全局配额、账户锁定、验证码、滑动窗口、令牌桶或网关级限流。
- 当前审计只覆盖五类白名单关键事件，不提供修改、删除或导出接口。

## 6. 面试复盘要点

1. MySQL 是最终真源，Redis 只保存 60 秒可重建快照；业务事务成功提交后才失效缓存。
2. 审核并发控制依赖数据库条件更新 `id + PENDING + version`，Redis 不能替代最终一致性约束。
3. RabbitMQ 使用至少一次投递，因此稳定业务消息 ID、数据库状态、唯一约束和任务行锁共同保证幂等。
4. 审计日志和业务事实共用事务；失败回滚时不能留下“假成功”审计记录。
5. 限流脚本使用 Lua 保证 `INCR + PEXPIRE + PTTL` 原子执行，但当前实现仍是单实例能力，不能夸大为分布式全局限流。

## 1. 意图与完成标准

用户要求补齐现有 demo 对项目业务与技术内容的覆盖。已确认的方案是：保留逐步演示，新增账户、交易、导入、对账、审核、审计统计和工程演示七个工作区，复用真实接口及已有查询分支，并以业务覆盖清单和真实浏览器验收为完成标准。

控制台同时服务两种用途：日常操作已有业务，以及在学习、面试中观察真实状态变化。写操作进入当前连接的数据库；异步结果来自任务查询；风控事实来自服务端；工程结果来自可核对的运行证据。

“补齐”的具体含义：

1. 当前全部业务 API 操作均有明确的页面入口和结果展示。
2. 列表支持实际分页及后端现有筛选字段，不截断为前 100 条。
3. 导入和对账支持历史查询、按 ID 找回及重新登录后的继续观察。
4. 对账全部结果类型、匹配方法和原因分支，以及三种风险规则均有可执行场景。
5. 已有可靠性、缓存、限流、监控、故障演练、性能、安全和 CI/CD 内容有对应演示入口与证据核对方法。
6. 交付项分别记录已实现、自动测试通过、真实运行验收通过及环境限制；不使用“完美覆盖”代替验收清单。

## 2. 当前差距与源码事实

现有页面位于 `src/main/resources/static/demo/index.html`，是一个 977 行的独立静态页面。它主要服务单批次的创建、导入、对账、审核和摘要查询，缺少常规管理、完整历史、逐行错误及完整场景构造。

当前业务基线有 23 个方法与路径组合。OpenAPI 的 18 个路径对象不等于 18 个操作。导入、对账 Controller 均没有集合 GET；浏览器无法从现有 API 查询所有历史任务。

现有查询分支已增加 `GET /api/auth/me` 和 `GET /api/review-tasks/{id}/context`，后者只允许 REVIEWER。复用时需要合并 `/demo/**` 静态资源规则与新增权限规则，并运行双方测试。

对账按 `importJobId` 发起；页面不会虚构“按业务日期创建任务”的参数。风险阈值、规则开关与窗口来自服务启动配置。大额默认 10000.00、疑似重复默认 5 分钟、高频默认 10 分钟内 5 笔支出，只能标为默认配置，不能标为当前环境实际配置。

## 3. 架构选择

采用 Spring Boot 同源静态页面与原生 JavaScript ES modules。保留 `/demo/index.html`，无需独立前端服务器、框架或产品构建依赖。

比较过的方案：

| 方案 | 取舍 |
| --- | --- |
| 同源页面、共用客户端、独立工作区模块（选定） | 复用当前部署方式，模块可以分别验证，足以支持全部现有业务 |
| 继续扩展单个内联 HTML | 起步改动较少，但已有长文件继续膨胀，状态与场景难以隔离 |
| 新建独立 SPA 与前端服务 | 适合更大产品，但增加构建、CORS 和部署成本，当前需求不需要 |

页面分为顶层会话栏、工作区导航、主内容区和可展开的最近操作记录。导航包括原有“逐步演示”及七个新增工作区。角色会影响可操作按钮，后端仍承担最终权限判断。

计划模块边界：

```text
src/main/resources/static/demo/
  index.html                    页面骨架、导航与入口
  styles.css                    布局、表格、表单、反馈与移动端样式
  js/app.js                     模块注册、导航、会话切换与任务定位
  js/api.js                     认证请求、错误解析、超时、取消与终态轮询
  js/session.js                 仅内存 Token 与服务端身份
  js/ui.js                      安全 DOM、分页、表单、状态与操作反馈
  js/workspaces/guided.js       保留原逐步演示
  js/workspaces/accounts.js     账户
  js/workspaces/transactions.js  交易
  js/workspaces/imports.js      导入
  js/workspaces/reconciliation.js 对账
  js/workspaces/reviews.js      审核
  js/workspaces/insights.js     审计与统计
  js/workspaces/engineering.js  工程状态、演练指南与证据
  js/scenarios.js               业务夹具配方与执行顺序
```

工作区通过共用客户端访问 API，通过 ID 关联业务事实，不直接操作其他模块的 DOM。共用客户端返回 HTTP 状态与业务数据；分页使用后端返回的 `page`、`size`、`total` 和 `records`，以实际响应字段为准。

## 4. 会话、权限与数据流

保留 ADMIN 与 REVIEWER 双会话用于角色分工演示，增加当前操作角色选择。每次登录后通过 `/api/auth/me` 显示服务端返回的身份；角色不由输入框标签推断。

Token 与密码不进入 localStorage、sessionStorage、Cookie、URL、日志或导出内容。成功登录后清空密码框；页面刷新需要重新登录。注销清除对应 Token，并取消其未完成只读请求。

首次业务写入沿用当前的数据持久化确认。删除、停用等操作另外展示目标 ID、名称及后果并要求用户确认；失败时保留输入和服务端错误。按钮在请求中禁用，成功后刷新受影响的数据。

任务定位通过输入 ID 或历史列表选择实现。可使用页面 hash 保存工作区及任务 ID，不包含凭据；刷新后先重新认证，再 GET 查回任务。新浏览器会话可从历史列表找回任务，不能依赖丢失的本地批次状态。

POST/PATCH/PUT/DELETE 不自动重试。任务创建收到 202 只显示已受理，保留任务 ID 并轮询终态；收到 200 的重复返回显示复用原任务。轮询默认每秒一次、上限 90 秒；超时保留最后状态并提供继续查询 GET，不重发创建请求。切换任务或离开工作区停止旧轮询，终态更新不得被过期响应覆盖。

## 5. 工作区与接口覆盖

### 5.1 账户

支持创建、详情、关键词/类型/状态筛选、分页、改名、启用/停用及软删除。显示唯一性、账户已使用而不能删除等真实错误。列表及详情提供跳转到账户交易的入口。REVIEWER 可读，ADMIN 可写。

覆盖：`POST/GET /api/accounts`、`GET/DELETE /api/accounts/{id}`、`PATCH /api/accounts/{id}/name`、`PATCH /api/accounts/{id}/status`。

### 5.2 交易

支持人工交易创建、详情、完整替换和软删除；按账户、方向、来源、外部流水号及时间范围筛选分页。金额使用十进制字符串提交，避免浏览器浮点运算改变金额。业务时间按接口的 LocalDateTime 契约提交，并明确页面采用的业务时区。

导入交易保留只读属性，由后端判断可修改性；界面说明 MANUAL 与 CSV 的区别，不提供绕过来源限制的操作。

覆盖：`POST/GET /api/transactions`、`GET/PUT/DELETE /api/transactions/{id}`。

### 5.3 导入

支持用户选择 CSV、预览内容、提交及状态轮询，展示总行数、成功/失败/重复行数和文件级错误；提供行错误分页，逐行显示错误码和原因。现有行错误接口仅支持 page/size，不宣称服务端错误码筛选。任务详情显示原文件名、创建者、时间及结果，能够跳转发起对账。

提供已生成文件的明确“重复提交验证”操作，复用完全相同的文件字节，比较原任务与返回任务 ID。它是用户主动演示幂等的操作，不是失败自动重试。普通文件导入与场景生成入口都支持这一验证。

覆盖：`POST /api/import-jobs`、`GET /api/import-jobs/{id}`、`GET /api/import-jobs/{id}/errors`；新增历史集合 GET 见第 6 节。

### 5.4 对账

从可用导入任务发起，展示创建响应、任务状态、四类结果计数及处理时间；逐笔结果按后端现有 resultType 筛选分页，并显示匹配方法与原因码。现有接口不支持按匹配方法或原因码筛选，不提供仅筛选当前页却冒充全局筛选的控件。显示关联 CSV 与人工交易 ID，并可跳转详情。

提供主动重复创建验证，比较返回任务 ID 与 `duplicateRequest`。历史任务可重新读取结果，不重新执行任务。

覆盖：`POST /api/reconciliation-jobs`、`GET /api/reconciliation-jobs/{id}`、`GET /api/reconciliation-jobs/{id}/results`；新增历史集合 GET 见第 6 节。

### 5.5 审核

支持按状态、任务来源、结果类型和规则码筛选分页；展示任务详情、版本、历史决策及关联对象。避免发送后端明确不允许组合的筛选条件，例如同时指定 `resultType` 与 `ruleCode`。

REVIEWER 可加载已有上下文接口，查看交易、账户摘要、对账事实与风险依据，随后填写备注并确认或忽略。ADMIN 可读原任务详情，但不得读取 REVIEWER 专有上下文或提交决策。

409 保留用户备注，提示重新加载当前版本，不自动覆盖或重试写入。已终结任务显示只读结果。演示模式可以保留旧版本，提交后验证并发保护的实际拒绝。

覆盖：`GET /api/review-tasks`、`GET /api/review-tasks/{id}`、`PATCH /api/review-tasks/{id}/decision`；复用 `GET /api/review-tasks/{id}/context`。

### 5.6 审计与统计

ADMIN 可以按动作类型、操作者筛选审计分页；选择日志查看安全字段及关联任务，跳转任务详情。现有审计接口没有任务 ID 筛选，单批次模式需遍历全部页后筛选，支持取消，不声称首页包含全部批次日志。

两角色均可刷新全数据库统计；卡片展示导入、对账、审核、风险规则的实际响应。全库统计与单批次结果分区展示，注明采集时间，不能将全库变化直接归因于当前批次。

覆盖：`GET /api/audit-logs`、`GET /api/statistics/overview`。

### 5.7 工程演示

工程区为每项能力提供“机制说明、执行入口、应观察的信号、当前证据及采集时间”。没有证据时显示未验证；历史报告注明日期与原环境，不自动标记当前成功。

| 能力 | 执行与观察方式 |
| --- | --- |
| 健康与监控 | 页面 GET `/actuator/health` 与 `/actuator/prometheus`，显示真实 HTTP 状态及选定指标；提供可配置 Prometheus/Grafana 链接 |
| 文件/请求幂等 | 跳转重复上传与重复对账场景，比较任务 ID、标记和数据库事实 |
| MQ、Outbox、ACK、重试、死信、消费者幂等 | 展示现有演练脚本命令、队列与数据库核对步骤；当前指标可读，消息与数据库证据需隔离脚本实际采集 |
| Redis 缓存与失效 | 展示统计读取、业务变更、再次读取步骤；缓存命中/TTL/失效的证明需现有中间件核对，不能从相同统计响应推断命中 |
| 限流与权限 | 提供角色权限验证和隔离环境的受控限流步骤；展示真实 401/403/429 与 Retry-After，不以按钮禁用证明后端权限 |
| 乐观锁 | 跳转保存旧版本的审核冲突场景，展示实际拒绝及刷新结果 |
| 故障恢复 | 提供已有 Redis 故障、MQ 重试、错误配置脚本与恢复检查步骤；页面停止响应时保留最后成功采集时间 |
| SQL 与压测 | 链接现有报告并提供执行计划、认证压测的复现入口；报告注明实际环境，拒绝将全 401 结果作为性能证据 |
| 安全、CI/CD 与部署 | 提供测试/发布/部署/回滚文档和证据入口，解释代码构建、线上运行与数据回滚的区别 |

浏览器不会直接取得 Docker、数据库或服务器凭据，也不新增远程 shell 或停服务 API。需要控制容器的演练由维护者在隔离环境运行仓库脚本；工程区负责提供步骤与观察实时信号。该边界在页面和覆盖清单中明确。

跨端口监控入口使用链接打开；不通过放宽 CORS 或代理任意 URL 获取外部服务。未启动 Prometheus/Grafana 时显示服务入口及未验证状态。

| 新接口 | 参数与返回 | 权限 |

## 7. 可执行业务场景

保留原手工调参流程，另加场景配方。每个场景显示将创建的账户/交易/文件、条件、预期类别和需要观察的响应。使用唯一 `DEMO-*` 前缀及账户隔离，避免已有数据污染候选与风险窗口。写入前预览；可按步骤执行和查看 ID。

| 分类 | 必须支持的场景 |
| --- | --- |
| 导入 | 全成功；合法行与错误行混合；文件级失败；完全相同文件复用任务；不同文件包含重复业务行 |
| 强键对账 | EXACT；三天内 TOLERANCE；DIRECTION_MISMATCH；AMOUNT_MISMATCH；TIME_OUT_OF_RANGE |
| 弱匹配对账 | 单候选 TOLERANCE；NO_CANDIDATE；MULTIPLE_CANDIDATES；MANUAL_ALREADY_MATCHED |
| 风险 | LARGE_AMOUNT；POSSIBLE_DUPLICATE；FREQUENT_TRANSACTION；默认边界附近的命中与不命中观察 |
| 审核 | CONFIRMED；IGNORED；旧 version 冲突；终态重复决策拒绝 |
| 权限 | 匿名读取拒绝；REVIEWER 业务写入拒绝；ADMIN 审核决策拒绝 |

预期与实际分开展示。场景配方遵循 matcher 的强键优先、人工交易预留及弱匹配规则；不会在前端计算结果后冒充服务端结果。风险场景显示规则实际返回；规则关闭或非默认阈值导致未命中时明确记录，不强制修改服务配置。

文件哈希去重、导入业务行重复、对账 DUPLICATE、POSSIBLE_DUPLICATE 风险命中分别展示，避免把不同机制混为同一种“重复”。

## 8. 错误处理、可用性与输出

统一展示 HTTP 状态、业务 code、简明 message 与字段错误；网络错误、请求超时、轮询上限及服务端失败分别表达。事件记录不输出密码、Token、授权头、完整请求或完整原始响应。

所有接口文本通过 `textContent` 等安全 DOM API 渲染；不将文件名、备注、描述或错误信息拼入 HTML。表单有标签，状态使用可访问提示，键盘可操作。窄屏导航折叠，表格允许横向滚动，关键操作与确认区保持可见。

覆盖与验收报告保存于 `docs/review/`。如果提供结果导出，仅包含显式选择的任务 ID、状态、HTTP/code、计数、场景名和采集时间；凭据与原始文件内容不导出。
